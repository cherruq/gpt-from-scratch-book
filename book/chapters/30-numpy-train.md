# 用 NumPy 从零训练 GPT

## 学习目标

串起前向、交叉熵、反向、裁剪、AdamW 和检查点，先复现单批过拟合，再训练小语料并精确续训。

## 前置知识

[[11|第 11 章]] 的 AdamW、[[15|第 15 章]] 的引擎、[[28|第 28 章]] 的完整模型和[[29|第 29 章]]的数据管线。

## 本章在 GPT 中的位置

这是基线的训练入口。NumPy 负责数组运算，梯度由前文实现。CPU 默认配置可以用短时间检验从随机初始化到生成的全链路。

## 单步与目标尺度

输入序列由老师提供（teacher forcing），同个批次计算各位置分数。令 \(\ell_{bt}=-\log p_{\theta}(Y_{bt}\mid X_{b,\le t})\)，则一次更新前的平均损失为 \(\sum_{bt}\ell_{bt}/(BT)\)。等长窗口中，每项权重均为 \(1/(BT)\)，反向自动包含该尺度。清空旧叶子梯度，执行反向，裁剪全局范数，再按 [[11#adamw]] 更新所有参与参数。若损失或梯度出现非有限数，停止该步并排查。

手算一个缩小的批次：若两个目标的预测概率分别为 \(1/4,1/2\)，均值为 \((\log 4+\log 2)/2=\log\sqrt 8\approx1.03972\)，困惑度为 \(\sqrt8\approx2.82843\)。这两个目标的每一行梯度各取对应 \(p-u\) 的一半。加入同样分布的重复批量，在均值定义下梯度不会加倍。

## 检查点与精确恢复

保存参数、AdamW 的 \(m,v\) 和步号、训练批次 RNG、分词器、配置及语料指纹。每次保存先在同目录写临时文件、刷盘，再替换正式文件。这样中途异常通常保留上一个完整的检查点。加载拒绝形状或数据、批大小、学习率不匹配的恢复。等价恢复依赖运算次序、数值后端及采样流未变。测试对比连续跑 12 步与跑 5 步再恢复到第 12 步，NumPy 参数、矩与 RNG 精确一致。

## Python 实验

M6，先运行 `python -m examples.preview`，确认同批损失 2.090428 → 0.015276。随后用下面命令分两段训练本地合成语料。第二条的 120 是最终步数。

~~~bash
OPENBLAS_NUM_THREADS=1 python -m src.numpy_gpt.train fit --config configs/quick.json --steps 60 --checkpoint runs/book.npz
OPENBLAS_NUM_THREADS=1 python -m src.numpy_gpt.train fit --config configs/quick.json --steps 120 --checkpoint runs/book.npz --resume
python -m src.numpy_gpt.train generate --checkpoint runs/book.npz --prompt 今早我 --top-k 8 --cache
~~~

### 第一次训练时逐层排错

先在固定批中选一组确定的输入位置，打印它的真实目标、目标概率和负对数，再对训练函数返回的均值做核对。若标签偏移错误，优化器也可能使错误目标的损失持续下降。添加一次权重更新后保留更新前参数副本，检查差分和实际变化。AdamW 的一步受历史矩与衰减影响，不能用每项都严格逆当前梯度作为断言。可用 [[11#adamw]] 的已知参数做首步核对，再看模型独立参数是否确实更新。

检验恢复时，从第 \(s\) 步记录的检查点必须重生第 \(s+1\) 步的批。日志中的第 \(s\) 步 batch loss 是参数更新前的值，保存的检查点则包含更新后参数和已消费这一批的随机状态。分开使用 <code>fit</code> 和 <code>generate</code>，可以独立复查 Token 表、上下文、模型权重和采样参数。

默认配置使用字符表。把 JSON 的 <code>tokenizer</code> 设为 <code>"bpe"</code>，并给 <code>vocab</code> 写 320，就能走字节级流程。两种模式都只在训练集实际拟合，会改变 ID、序列长度、有效评估项及 LM Head 尺寸。用另一个检查点路径保存；比较跨分词模型时，可在相同文本边界上补测每 UTF-8 字节的负对数似然。

### 手算一次全局裁剪与 AdamW 首步

把所有叶子的梯度想象成拼接的一条向量。若其二范数 \(n\) 超过阈值 \(c\)，每个叶子乘同一个系数 \(c/n\)。检查裁剪前日志高于阈值并不等于裁剪失败，因为训练返回的正是**裁剪前**范数。

只取一组权重 \(w=[2,-1]\)，原始梯度 \([3,4]\)，阈值 1。范数为 5，实际进 AdamW 矩估计的梯度为 \([0.6,0.8]\)。从两组零矩开始，取 \(\beta_1=0.9,\beta_2=0.999\)，首步的 \(m=[0.06,0.08]\)、\(v=[0.00036,0.00064]\)。首步用各自的 \(1-\beta\) 做偏差纠正，得到 \(\widehat m=[0.6,0.8]\) 与 \(\widehat v=[0.36,0.64]\)。学习率 0.1、衰减 0.2 时，权重先乘 0.98，再减去约 \([0.1,0.1]\)，结果约 \([1.86,-1.08]\)，省略量是分母里 \(10^{-8}\) 带来的最后几位。单步检验可顺序打印原始范数、矩和更新后的参数。

::source examples/training_labs.py clipping

### 故意训练错一个标签

使用与第 1 章相同的两条轮换记录和种子，各训练 80 步。对照组把目标切片错误地设成输入本身，两组分别在自己的目标及真正的下一 Token 上计分。

| 更新所用目标 | 最后对所用标签的 NLL | 最后对真实下一 Token 的 NLL |
| --- | ---: | ---: |
| 下一 Token | 0.015276 | 0.015276 |
| 当前位置 | 0.012340 | 9.617911 |

错误版的训练 NLL 更低，恰好因为它用当前位置能够直接学到抄写。它在相同批次的真正下一项任务上明显失败。调试时先逐行核对 \(Y_{bt}=R_{b,t+1}\)，再比较正确目标下的损失、贪心输出及真标签概率。一个初始接近均匀的模型在两类任务上都可产生接近 \(\log V\) 的损失，因此单看初始损失也不足以验收标签。

### 续训首批和验证分组

快速配置再做连续 6 步与 3+3 步对照。检查点恢复后的第一个批次索引为 \([5521,5711,5383,5898]\)。若错误地从原种子重建 RNG，则拿到第一步的 \([669,5807,4911,3293]\)，即使恢复的权重正确，下一步的训练输入也不同。检查参数、两阶优化器矩和最终 RNG，当前 CPU 实验逐元素一致。使用 GPU、不同后端或不同 dtype 时，应重新建立容差和复现要求。

再按 [[29|第 29 章]] 的窗口分组复跑 120 步。完全出现在训练窗口集合中的验证窗口共有 896 个目标，NLL 为 1.283947；其余 256 个目标的 NLL 为 2.393287。汇总以目标数作权重，得到 \((896\,L_{\rm seen}+256\,L_{\rm unseen})/1152\approx1.530467\)。后一个子集仍源自同模板，可能共享较短子串。这个比较具体说明了整体得分的来源。

## 常见错误

- 复用旧计算图而就地修改了权重。
- 从上一次继续训练却重新初始化随机流。
- 把训练批和验证统计混用。日志的训练值来自该步更新前，验证值在该步更新后重新前向。

## 练习

1. **基础。** 长度 T 的单样本训练包含几个监督项？
2. **推导。** 为什么恢复时 Adam 的步号会影响下一次更新？
3. **工程。** 分两段训练并用测试比较最终参数。
4. **开放探索。** 训练越久验证 NLL 是否必降？怎样判定何时停止？

<details markdown="1">
<summary>参考答案</summary>

1. 用 \(T+1\) 项窗口构造，因此有 \(T\) 个监督项。
2. 矩的偏差纠正分母含 \(1-\beta^t\)，步号错误会改更新幅度。
3. 运行 `python -m pytest tests/test_training.py -q`，也可用独立检查点复跑长配置。
4. 预先定义独立验证指标和观察间隔，保存验证最好的检查点，避免根据测试集调整训练规则。
</details>

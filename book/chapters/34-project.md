## 本章在 GPT 中的位置

## 配置到日志

训练配置包含词表拟合方式、最大上下文、隐藏宽度、头数、扩维、层数、batch、总步数、学习率和种子。默认 CPU 可运行。每条 JSON 日志包含步号和验证目标计数，可将训练批值与固定验证曲线关联。PyTorch 支持指定设备、dtype、是否启用 SDPA；若需 CUDA 按设备安装兼容的 PyTorch 发行包并设 `--device cuda`，此项目的实测表使用 CPU。

快速配置 \(C=16,H=4,L=2,T=16,F=48\)，由训练集拟合的实际词表 \(V=124\)。用 [[28#parameter-count]] 手算 Token 表 1984、位置表 256。每块两组 Norm 64、MHA 1088、FFN \(2\cdot16\cdot48+48+16=1600\)；最终 Norm 32。总数为 \(1984+256+2\cdot2752+32=7776\)。

较大配置 \(C=128,H=4,L=4,T=128,F=512,V=124\)，共 825600 参数。仅 float32 权重是 \(825600\cdot4=3302400\) 字节，约 3.15 MiB。若再存同规模梯度和 AdamW 的两阶状态，至少约 12.60 MiB，未包括激活、框架分配和临时缓冲。训练每步有 \(B T=512\) 个目标，150 步一共 76800 个训练目标，重复采样会产生重复监督。

## Python 实验

M7，普通环境先按 README 装 PyTorch 后运行下列命令。较大运行在 i7-10700 单 Torch 线程上用 9.23 秒（含进程启动和验证），第 150 步验证 NLL 从 4.82309 降到 0.13034。验证使用 1024 个目标。此配置因上下文和窗口划分不同，不与 [[32|第 32 章]] 的 PPL 做同目标的严格横向比较。

~~~bash
python -m src.torch_gpt.train fit --config configs/larger.json --checkpoint runs/larger.pt --sdpa
python -m src.torch_gpt.train generate --checkpoint runs/larger.pt --prompt 今早我 --top-k 8
# 继续到第 180 步，需保持 sdpa、dtype 及其他训练配置
python -m src.torch_gpt.train fit --config configs/larger.json --checkpoint runs/larger.pt --sdpa --steps 180 --resume
~~~

生成命令把 Torch 权重转给 NumPy，复用同一采样与 KV 缓存示例。记录的生成开头为「今早我走到窗前，看见了夏风。我在纸上写下地点和天气，给」。继续到 180 步是命令示例，报告仅记录实测到第 150 步。

::source src/torch_gpt/train.py torch_fit

## 常见错误

- 认为配置的词表上限就是实际词表大小。
- 使用不同序列长度和有效目标数时直接比较验证 PPL。
- 恢复检查点时加载模型却丢弃优化器状态。

## 练习

1. **基础。** 较大配置每个训练 batch 有多少监督项？
2. **推导。** 计算该配置仅权重与两个 AdamW 矩的字节数。
3. **工程。** 将训练拆成两段，确保步号和日志可追溯。
4. **开放探索。** 如何比较 CPU 和 GPU 的每步耗时？

<details markdown="1">
<summary>参考答案</summary>

1. 512。
2. \(3\cdot825600\cdot4=9907200\) 字节。
3. 保留第一次的日志，再用追加重定向保存恢复日志，核对首条验证步号和最终步。
4. 固定软件、形状和数值模式，预热并在计时边界同步 GPU，区分数据拷贝和算子时间。

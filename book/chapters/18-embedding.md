# One-hot 与 Embedding

## 学习目标

从字节级 BPE 的 ID 构造 Embedding 输入，推导查表与独热（one-hot）乘法的等价性。手算重复 Token 的散射梯度，区分输入查表与共享输出头的梯度来源。

[[05|第 5 章]] 的矩阵乘法、[[15|第 15 章]] 的索引 VJP、[[17|第 17 章]] 的 ID。

## 本章在 GPT 中的位置

嵌入（embedding）表 \(E[V,C]\) 把每个 Token ID 对应到通道向量，基线也用同一参数的转置作为输出头。

## 从稀疏选择到查表

对 ID \(i\)，定义 one-hot 行 \(o[1,V]\)，仅第 \(i\) 项为 1。于是 \(oE=\sum_v o_v E_{v,:}=E_{i,:}\)，归约沿词表轴。把整数输入 \(I[B,T]\) 按行展平，位置 \((b,t)\) 的平面下标为 \(n=bT+t\)。令 \(N=BT\)，定义 \(O[N,V]\)，满足 \(O_{nv}=\mathbf{1}[I_{bt}=v]\)。输出 \(X[B,T,C]\) 的通道 \(c\) 为：

$$ gather-equivalent
X_{btc}=\sum_{v=0}^{V-1}O_{bT+t,v}E_{vc}=E_{I_{bt},c}.
$$

计算时可以直接用 <code>E[I]</code> 取出每个位置所指的整行。这称为收集（gather）。查表生成 \(BTC\) 个浮点输出，省去构造 \(BTV\) 项的独热矩阵。实际模型按固定随机种子初始化 \(E\)，用训练损失更新。ID 是离散的行号，反向只需沿着被读到的行传给表参数。相同 ID 在输入嵌入这一步读取同样的行，后续的位置嵌入与上下文计算会让它们的表示产生差异。

## 从一次读取到多位置累加

固定 \(I\)，把上游 \(G[B,T,C]\) 看作损失对 \(X\) 的偏导。对 \(E_{vc}\) 加一个微小扰动，只有 \(I_{bt}=v\) 的位置在同一通道收到这个扰动。把 \(dX_{btc}=dE_{I_{bt},c}\) 代入 \(d\mathcal L=\sum_{b,t,c}G_{btc}\,dX_{btc}\)。按表行重新分组后，\(dE_{vc}\) 的系数就是所有命中位置在该通道上的梯度之和。

$$ scatter
\overline E_{vc}=\sum_{b,t:I_{bt}=v}G_{btc}.
$$

若把 \(G\) 展平成 \(G_{\rm flat}[N,C]\)，同一个公式写成 \(O^\mathsf T G_{\rm flat}[V,C]\)，归约沿 \(N\) 轴，通道之间没有求和。实际反向从全零梯度表出发，将每个位置的 \(G_{bt,:}\) 加到指定行。这称为散射加（scatter-add）。同一 ID 可能在一个样本里重复，也可能被不同批次行共同引用，两类重复都要相加。例如 \(I=[[1,1],[2,1]]\)，若四个位置按行收到 \([1,2],[2,3],[3,4],[4,5]\)，第 1 行累计 \([1,2]+[2,3]+[4,5]=[7,10]\)，第 2 行是 \([3,4]\)。

NumPy 的普通高级索引更新可能先收集临时值，再覆盖写回。把全零数组做 `a[[0,0]] += 1`，第 0 项只得到 1。基线的 `Tensor.__getitem__` 调用 `np.add.at(buffer, index, gradient)`，让重复索引的每份贡献都进入同一个位置。[NumPy 2.3 的 ufunc.at 文档](https://numpy.org/doc/2.3/reference/generated/numpy.ufunc.at.html)

共享输出头在隐藏 \(Z[B,T,C]\) 上计算 \(ZE^\mathsf T\)，沿通道归约得到 \([B,T,V]\)。展平后的 \(Z[N,C]\) 与输出上游 \(U[N,V]\) 使输出路径对表贡献 \(U^\mathsf T Z[V,C]\)，沿位置轴归约。这与输入查表的梯度相加。当 ID \(v\) 没有出现在输入中，第 \(v\) 行的输入梯度为零，仍有可能从输出类别 \(v\) 收到梯度。[[28|第 28 章]] 会在完整 GPT 中分别测量这两项。

## 手算从「春春」到梯度

取 [[17|第 17 章]] 的两轮合并结果，连同边界符得到单行输入 \([256,259,259,257]\)，所以 \(B=1,T=4,V=260\)。为便于复算，实验把通道数设为 2，表行固定为 \(E_{v,:}=[v,-v]\)。令第 \(j\) 个位置从 1 计，上游为 \([j,j+1]\)。逐行查表并记下反向的去向。

| 位置 j | Token ID | 前向读取的行 | 反向加到该 ID |
| ---: | ---: | --- | --- |
| 1 | 256 | [256,−256] | [1,2] |
| 2 | 259 | [259,−259] | [2,3] |
| 3 | 259 | [259,−259] | [3,4] |
| 4 | 257 | [257,−257] | [4,5] |

输出形状为 \([1,4,2]\)，逻辑独热矩阵为 \([4,260]\)。梯度表的 259 行得到 \([2,3]+[3,4]=[5,7]\)。256 和 257 各有一次贡献，其余 257 行的输入梯度为零。实验保留完整带边界序列以观察这两行。后续 [[29|第 29 章]] 构造单条记录的下一 Token 监督时，用前三项预测后三项，因此 EOS 在这里是最后一个监督目标。

用 \(\mathcal L=\sum_{b,t,c}X_{btc}G_{btc}\) 固定这个上游。各位置两项之和等于 \(-I_{bt}\)，默认损失为 \(-1031\)。只扰动 \(E_{259,0}\)，会改变两个位置的前向。步长 \(h=0.125\) 时，两个损失为 \(-1030.375\) 与 \(-1031.625\)，中心差分为 \(1.25/0.25=5\)，恰好等于累加后的第 0 通道梯度。目标对该参数是线性的，中心差分没有截断误差；这里的整数与二进制步长也可以在 float64 中精确表示。

## 手算重复 ID

令表行依次是 \([1,2],[3,4],[5,6]\)，取 ID \([1,1,0]\)。前向取 \([[3,4],[3,4],[1,2]]\)。三条上游梯度为 \([1,1],[2,3],[4,5]\)，反向表结果为 \([[4,5],[3,4],[0,0]]\)。如果输出头也使用此表，再加输出路径矩阵。

::demo embedding 改变第二个 ID，追踪查表和累加

## 常见错误

- 把 reshape 后 \([N,V]\) 的 one-hot 当参数保存，引入与序列长度相关的巨大临时数组。
- 用重复索引做普通 NumPy 高级索引加法，遗漏贡献。
- 复制两份同值矩阵并期待梯度自动相加。共享应指同一参数对象沿两路径使用。
